# 树莓派重装与视觉程序部署手册

本文用于 TF 卡损坏后的重新部署。目标是让树莓派恢复到能够稳定取图、运行视觉代码、驱动 OLED，并通过 UART 向 STM32 发送识别结果的状态。

项目代码仓库：`https://github.com/Pluto-KCL/racecar.git`

整个过程按硬件依赖从少到多进行。每完成一个阶段先验收，再进入下一个阶段。不要一开始同时连接摄像头、OLED、颜色传感器、STM32 和电机。

## 一、准备材料

需要准备以下设备：

- Raspberry Pi 4B 和稳定的 5V 电源
- 新的 TF 卡，建议 32 GB 或更大容量
- CSI 摄像头和排线
- OLED SSD1306
- TCS34725 颜色传感器（可选）
- USB 转串口模块或 STM32 开发板
- 电脑、读卡器和网线或 Wi-Fi

电脑上需要准备 Raspberry Pi Imager、Git、SSH 客户端，以及用于保存代码和系统镜像的硬盘或 U 盘。

## 二、烧录树莓派系统

1. 打开 Raspberry Pi Imager。
2. 选择 Raspberry Pi 4 使用的 Raspberry Pi OS 64-bit。
3. 选择新的 TF 卡。
4. 在高级设置中配置主机名、用户名、密码、Wi-Fi、`Asia/Shanghai` 时区和 SSH。
5. 开始烧录并等待校验完成。
6. 将 TF 卡插入树莓派并上电。

首次启动后，在电脑上连接树莓派：

```bash
ssh 用户名@racecar-pi.local
```

如果 `.local` 无法解析，可以在路由器后台查看树莓派 IP，再使用：

```bash
ssh 用户名@树莓派IP地址
```

登录后确认系统信息：

```bash
hostname
hostname -I
cat /etc/os-release
```

验收结果应为能够登录、能够联网、能够看到 IP 地址。

## 三、更新系统并开启硬件接口

```bash
sudo apt update
sudo apt full-upgrade -y
sudo raspi-config
```

在配置界面开启 I2C、UART 和摄像头。UART 配置中关闭串口登录 shell，开启硬件串口功能。完成后重启：

```bash
sudo reboot
```

重连后检查：

```bash
ls -l /dev/serial0
sudo apt install -y i2c-tools
sudo i2cdetect -y 1
```

如果还没有连接 I2C 设备，扫描表可以为空。此时只需要确认命令可以执行。

推荐使用 HTTPS：

cd ~

cd racecar
git status

配置了 GitHub SSH 密钥时也可以使用：

```bash

```

如果树莓派上产生了本地修改，先查看：

```bash
git status
git diff
```

## 五、安装 Python 和视觉依赖

摄像头和 OpenCV 依赖优先使用树莓派系统包安装：

```bash
sudo apt install -y \
  python3-picamera2 \
  python3-opencv \
  python3-numpy \
  python3-pil \
  python3-smbus \
  python3-pip \
  python3-venv \
  i2c-tools
```

建立带系统包访问权限的虚拟环境：

```bash
cd ~/racecar
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r vision/requirements.txt
python -m pip install luma.oled smbus2 pillow pyserial
```

每次重新登录后进入项目都执行：

```bash
cd ~/racecar
source .venv/bin/activate
```

检查依赖：

```bash
python -c "import cv2, numpy, serial; print('python dependencies OK')"
python -c "from picamera2 import Picamera2; print('picamera2 OK')"
```

## 六、单独测试 CSI 摄像头

连接 CSI 排线时关闭树莓派电源，确认金属触点方向和接口锁扣正确。

```bash
cd ~/racecar
source .venv/bin/activate
python vision/tools/capture.py --label test --n 5 --interval 1
```

照片默认保存在 `media/capture/test/`。检查图像是否全黑、倒置、偏色、拖影，以及赛道前方和颜色区域是否都能进入画面。

摄像头正常后，把照片和当前配置备份到电脑。

## 七、单独测试 OLED 和 I2C 设备

OLED 常见接线如下：

| OLED 引脚 | 树莓派 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO2，物理引脚 3 |
| SCL | GPIO3，物理引脚 5 |

扫描地址：

```bash
sudo i2cdetect -y 1
```

项目默认 OLED 地址为 `0x3C`。如果实际地址不同，在 `vision/config.py` 中修改 `OLED_I2C_ADDR`。

运行主程序但暂时关闭 UART：

```bash
cd ~/racecar
source .venv/bin/activate
python vision/main.py --no-uart
```

此时应能看到启动信息和 OLED 输出。按 `Ctrl+C` 停止。没有 OLED 时，程序会退化为控制台输出。

## 八、测试 TCS34725 颜色传感器

TCS34725 与 OLED 共用 I2C，总线地址通常为 `0x29`。连接后执行：

```bash
sudo i2cdetect -y 1
cd ~/racecar
source .venv/bin/activate
python vision/tcs34725.py
```

依次放置红、绿、蓝、黄目标，记录输出是否稳定。当前主程序使用摄像头识别颜色，TCS34725 主要用于单块颜色测量和校准。

## 九、运行视觉程序并采集真实样本

赛题中的指示牌是蓝底白色左转或右转箭头，颜色区域由四个色块组成。调参必须使用实际摄像头、实际安装姿态和接近比赛的光照。

采集指示牌样本：

```bash
python vision/tools/capture.py --label left --n 30 --interval 0.5
python vision/tools/capture.py --label right --n 30 --interval 0.5
python vision/tools/capture.py --label none --n 30 --interval 0.5
```

调试和回放：

```bash
python vision/tools/tune_sign.py media/capture/left
python vision/tools/tune_sign.py media/capture/right
python vision/tools/replay.py media/capture/left --kind sign
python vision/tools/replay.py media/capture/right --kind sign
python vision/tools/replay.py media/capture/none --kind sign
```

指示牌测试应检查左箭头和右箭头在画面左侧、中央、右侧时都能正确判断，无标志时不会频繁误报。现有 `sign.py` 仍需要根据真实蓝底白箭头标志继续完善。

## 十、调试颜色顺序

颜色样本应覆盖不同排列、距离和光照。需要实际确认四个色块在图像中的排列方向、图像方向是否等于车辆行驶顺序、是否需要透视校正、相邻同色块如何分离，以及四个位置是否可能出现重复颜色。

赛题允许每个位置从红、绿、蓝、黄中选择，因此识别逻辑不能要求四种颜色各出现一次。最终应按四个位置逐个判断，并把完整顺序持续显示在 OLED 上。

颜色参数位于 `vision/config.py`：

- `COLOR_HSV`
- `COLOR_MIN_AREA`
- `COLOR_DETECT_EVERY`
- `COLOR_CONFIRM_FRAMES`
- `COLOR_ORDER_REVERSED`

每次只修改一个参数，并记录测试结果。修改后运行：

```bash
python -m unittest discover -s vision/tests -v
```

## 十一、测试 UART 通信

树莓派与 STM32 连接前确认电源关闭。UART 只连接 TX、RX、GND，双方必须共地，信号电平为 3.3V。

项目默认配置为：

```python
SERIAL_PORT = "/dev/serial0"
SERIAL_BAUD = 115200
```

使用 USB 转串口调试时，可以临时改为对应设备，例如 `/dev/ttyUSB0`。

数据帧固定为 7 字节：

```text
AA 55 sign color_valid color_seq quality checksum
```

先运行：

```bash
python vision/main.py --no-uart
```

确认视觉输出后再运行：

```bash
python vision/main.py
```

用电脑端工具观察连续帧：

```bash
python tools/view_frames.py --port 串口设备
```

检查帧头、帧长、左右编码、颜色编码、校验和，以及断线和重连行为。

## 十二、与 STM32 联调

联调顺序如下：

1. STM32 只接收并打印 `sign`。
2. 测试左转、右转和无标志。
3. 测试低质量结果不触发转向。
4. 测试连续多帧确认。
5. 测试一个标志只触发一次。
6. 接入循迹和分岔控制。
7. 测试视觉板断电或串口断开时车辆的安全行为。

树莓派负责识别和上报，STM32 负责循迹、避障、选路和电机控制。两边的帧格式必须遵守 `docs/03_接口协议.md`。

## 十三、设置开机自动运行

手动运行稳定后再配置 systemd：

```bash
sudo nano /etc/systemd/system/racecar-vision.service
```

写入以下内容，并将用户名替换成树莓派实际用户名：

```ini
[Unit]
Description=Racecar vision service
After=network-online.target

[Service]
User=你的用户名
WorkingDirectory=/home/你的用户名/racecar/vision
ExecStart=/home/你的用户名/racecar/.venv/bin/python /home/你的用户名/racecar/vision/main.py
Restart=on-failure
RestartSec=2

[Install]
WantedBy=multi-user.target
```

启用服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable racecar-vision
sudo systemctl start racecar-vision
systemctl status racecar-vision
journalctl -u racecar-vision -f
```

## 十四、备份节点

建议在以下节点分别备份：

1. 系统刚烧录并能 SSH 登录。
2. 系统接口配置完成。
3. Python 依赖安装完成。
4. 摄像头能保存照片。
5. OLED 能显示文字。
6. 视觉程序能在 `--no-uart` 模式运行。
7. UART 能连续发送正确帧。
8. 整车完成一次完整测试。

代码备份使用 Git：

```bash
cd ~/racecar
git add vision docs
git commit -m "完成树莓派视觉环境部署"
git push origin main
```

如果暂时没有 GitHub 写权限，至少把整个项目目录复制到电脑或 U 盘。

系统稳定后制作 TF 卡镜像，并保留一张备用 TF 卡。代码和系统镜像应分别保存。

## 十五、常见问题

### SSH 无法连接

确认树莓派和电脑在同一网络，树莓派本地执行：

```bash
hostname -I
sudo systemctl status ssh
```

### 摄像头无法识别

关闭电源后重新插拔 CSI 排线，确认排线方向和接口锁扣，再检查 Picamera2 是否安装。

### I2C 扫描不到 OLED

检查 SDA、SCL、供电和共地。OLED 地址可能是 `0x3C` 或 `0x3D`，以扫描结果为准。

### 串口设备不存在

确认 UART 已在 `raspi-config` 中开启，并检查：

```bash
ls -l /dev/serial0
```

### 程序启动后识别结果不稳定

先保存真实图片，再调 ROI、曝光、HSV 阈值和最小面积。不要只在宿舍静态画面上调整参数。

### TF 卡再次损坏

检查电源是否稳定，避免突然断电。系统稳定后制作镜像备份，代码始终推送到 GitHub，并保留一张备用 TF 卡。
