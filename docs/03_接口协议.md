# 接口协议（唯一定义处）

> 树莓派 → STM32，单向为主。**两边代码都必须和这份文件一致。改协议 = 改这里 + 两边同时改 + 群里说。**
> 版本 v1.0（2026-11-09），对应计划《执行版》第三节。

## 1. 物理层

| 项 | 值 |
|---|---|
| 接口 | UART，3 线（TX / RX / GND） |
| 电平 | 两边都是 **3.3V，直连**。禁止 5V 信号进 GPIO |
| 波特率 | **115200**，8-N-1，无流控 |
| 树莓派 | `/dev/serial0`（GPIO14=TXD, GPIO15=RXD），需 `enable_uart=1` |
| STM32 | USART1：PA9=TX，PA10=RX |

## 2. 帧格式（7 字节，定长）

```
字节:  0     1     2      3            4          5        6
     0xAA  0x55  sign  color_valid  color_seq  quality  checksum
```

| 字节 | 名称 | 取值 | 说明 |
|---|---|---|---|
| 0 | 帧头1 | `0xAA` | 固定 |
| 1 | 帧头2 | `0x55` | 固定 |
| 2 | `sign` | 0 / 1 / 2 | 0=无，1=左转，2=右转 |
| 3 | `color_valid` | 0 / 1 | 颜色顺序是否有效 |
| 4 | `color_seq` | 0x00–0xFF | 4 个颜色压缩成 1 字节，见 §3 |
| 5 | `quality` | 0–100 | 本次识别置信度，低置信时 STM32 可降速 |
| 6 | `checksum` | — | `sign ^ color_valid ^ color_seq ^ quality`（异或，不含帧头） |

### 发送频率

- 目标 **20–30 Hz**（每 33–50 ms 一帧）。
- 连续发，不管有没有识别到：没有就发 `sign=0, color_valid=0`。
- **不要做"有事才发"**：STM32 靠帧间隔判断视觉板是否还活着。

## 3. 颜色顺序编码（`color_seq`）

4 个色块，每块 2 bit，**先看到的放在高位**：

```
bit7-6 = 第 1 个色块
bit5-4 = 第 2 个色块
bit3-2 = 第 3 个色块
bit1-0 = 第 4 个色块
```

单块颜色编码：

| 编码 | 颜色 |
|---|---|
| 0 | 红 |
| 1 | 绿 |
| 2 | 蓝 |
| 3 | 黄 |

**示例**：红-绿-蓝-黄 → `00 01 10 11` = `0b00011011` = **0x1B**

解码（两边都要能算）：

```c
// STM32
uint8_t c[4];
for (int i = 0; i < 4; i++) c[i] = (color_seq >> (6 - 2 * i)) & 0x03;
```

```python
# 树莓派
seq = (c0 << 6) | (c1 << 4) | (c2 << 2) | c3
```

> 只有 `color_valid=1` 时 STM32 才读取 `color_seq`；为 0 时忽略（可能是半帧/误识）。

## 4. 时序与保护（STM32 侧必须实现）

| 保护 | 阈值 | 动作 |
|---|---|---|
| 串口超时 | **200 ms 没收到帧** | 停视觉相关决策，按最后一次 `sign` 走完或直接减速到 0 |
| 低置信 | `quality < 40` | 不执行 `sign` 转向，只保持循迹 |
| 多帧确认 | 连续 **3 帧** `sign` 相同 | 才认定这个指示牌（防单帧误识） |
| 指示牌只生效一次 | 执行后锁存 3 s | 防止同一个牌被反复触发 |

**这些保护是 C 的责任，B 不要替 C 实现。** B 只需要如实给出 `quality`。

## 5. 对照自检（联调第一步）

1. 树莓派跑 `python3 vision/main.py`，串口打开发送。
2. PC 跑 `python tools/view_frames.py --port COM5`（STM32 的 USB 串口，或直接用 USB-TTL 夹在 TX 上）。
3. 看到连续帧，且 `checksum` 从不报错 → 物理层和协议都对。
4. 再跑 `python tools/simulate_vision.py --port COM5` 单独测 STM32 的解析。

## 6. 反向通道（可选，仅调试）

STM32 → 树莓派默认**不发**。调试时可以临时发 ASCII 行（`\n` 结尾）：

```
DBG err=-120 pwm_l=+35 pwm_r=+45 st=RUN
```

树莓派端不解析，只往日志里抄。**正式版本关掉**（省 CPU、免干扰）。
